# Separate building the version 2 writer from enabling it

Cyd Mobile builds and tests its Bluesky version 2 writer as soon as the work is ready, and gates only user-facing export on reader release and the bidirectional conformance matrix. The original precondition closed with issue #90, which preserves full-size images and full video locally, so nothing remains to gate writer construction; the surviving concern is shipping export to people before readers are proven, which issue #100 covers. Building the writer early is deliberate rather than incidental: it is the only component that can turn Bluesky saved data into a Cyd Bluesky archive, so it is what lets every later reader issue test against real data instead of synthetic fixtures alone. Until #100 passes, export stays behind a development-only affordance and Cyd Mobile claims no complete Bluesky version 2 conformance.
