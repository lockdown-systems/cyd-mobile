# Separate building the version 2 writer from enabling it

Cyd Mobile builds and tests its Bluesky version 2 writer as soon as the work is ready, and gates only user-facing export on reader release and the bidirectional conformance matrix. The original precondition closed with issue #90, which preserves full-size images and full video locally, so nothing remained to gate writer construction; the surviving concern was shipping export to people before readers were proven, which issue #100 covers. Building the writer early was deliberate rather than incidental: it is the only component that can turn Bluesky saved data into a Cyd Bluesky archive, so it is what let every later reader issue test against real data instead of synthetic fixtures alone.

Issue #100 has now passed that gate, and export is a user-facing capability offered from the app-wide menu beside import. What replaced `__DEV__` is not a date or a judgement call but a runnable one: `npm run test:archive-matrix` names every conformance row the writer's release depends on, ties each to the tests that prove it, and fails both when a row goes red and when the test behind one has been renamed or deleted. It runs in CI on every push. A row that loses its evidence un-enables the writer in exactly the way a broken row does.

The reader-before-writer ordering itself is unchanged and still binds the next version: ship and verify readers for a Cyd Bluesky archive version before enabling the writer for it (ADR 0008, ADR 0016).
